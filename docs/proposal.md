# AI 双语文章阅读助手 — 产品需求文档

> 真实网站与边界场景的验收结果见 [acceptance.md](./acceptance.md)。

## 1. 项目定位

这是一个供个人日常使用的 Chrome 扩展 Demo：提取当前英文网页的正文，调用 AI 翻译，并在浏览器侧边栏中阅读原文和译文。

本阶段的目标不是搭建完整产品架构，而是先把高频阅读流程做顺手：**打开文章 → 一键翻译 → 双语阅读 → 随手查词 → 保存或复制结果**。

## 2. 目标用户

- 主要用户是项目作者本人。
- 适合阅读英文技术文章、博客、新闻和文档。
- 完成后可作为简历中的 Chrome 扩展作品进行展示。

## 3. Demo 已有能力

- 使用 Readability 提取网页正文。
- 将正文转换为 Markdown。
- 通过 OpenAI 兼容接口进行流式翻译。
- 在 Side Panel 或 Result 中切换仅译文、双语和仅原文模式。
- 取消或重新开始翻译，并显示主要错误状态。
- 翻译选中文字，保存并管理最近 20 篇结果。
- 配置并测试 OpenAI 兼容的 API Key、模型和 Base URL。
- 复制仅译文或双语 Markdown，下载双语 Markdown。

## 4. Demo 功能范围

### 4.1 侧边栏阅读

- 从 Popup 一键打开 Chrome 侧边栏并翻译当前文章。
- 翻译时原网页保持可见，减少来回切换页面。
- 独立结果页继续保留，作为兼容入口。

### 4.2 双语阅读模式

- 支持“仅译文”“双语对照”“仅原文”三种模式。
- 双语模式按原文在上、译文在下展示。
- 记住用户最后一次选择的阅读模式。

Demo 阶段不做逐段严格对齐，先保证完整原文和完整译文都能方便阅读。

### 4.3 翻译过程控制

- 显示提取、连接模型、翻译中、完成和失败等明确状态。
- 翻译中可以取消。
- 失败或取消后可以重新翻译。
- 不做分段队列、断点续传和失败分段重试。

### 4.4 划词翻译

- 用户在网页选中文字后，可通过右键菜单发起翻译。
- 结果显示在侧边栏，并支持复制。
- 划词结果不覆盖当前整篇文章的翻译结果。

### 4.5 简单历史

- 自动保存最近 20 篇翻译结果。
- 可查看、重新打开和删除单条记录。
- 数据继续使用 `chrome.storage.local`，不引入 IndexedDB、收藏、搜索和云同步。

### 4.6 设置与连接测试

- 保留 API Key、模型和 Base URL 设置。
- 模型允许手动输入，便于使用其他 OpenAI 兼容模型。
- 增加“测试连接”，保存前即可确认配置是否可用。

### 4.7 复制与导出

- 可复制仅译文 Markdown。
- 可复制或下载双语 Markdown。
- 保留来源标题和原文链接。

## 5. 核心使用流程

1. 用户首次进入设置页，填写模型配置并测试连接。
2. 用户打开一篇英文文章，点击插件图标。
3. 点击“一键翻译”，侧边栏打开并开始翻译。
4. 用户在三种阅读模式之间切换，并可随时取消或重新翻译。
5. 遇到不理解的句子时，选中文字并用右键菜单翻译。
6. 翻译完成后，结果进入最近历史，并可复制或下载。

## 6. Demo 阶段不做

- 不做账号、付费、云同步和跨设备同步。
- 不做 IndexedDB、Repository 分层和通用任务引擎。
- 不做复杂并发调度、跨设备断点续传和缓存指纹。
- 不做术语表、多套翻译风格和多服务商管理系统。
- 不做 PDF/OCR、视频字幕、网页原位替换或 AI 问答。
- 暂不进行 Chrome Web Store 的安全、隐私和素材专项；个人试用稳定后再处理。

## 7. Demo 验收标准

1. 普通英文文章可被提取，并在侧边栏完成翻译。
2. 原网页和侧边栏可同时阅读。
3. 三种阅读模式可以切换，重新打开后仍保留上次选择。
4. 翻译过程有明确反馈，可以取消、失败后重试。
5. 右键可翻译选中文字，且不覆盖整篇文章结果。
6. 最近 20 篇翻译可打开和删除。
7. 模型配置可以测试，错误时给出可理解的提示。
8. 译文或双语 Markdown 可以复制，双语 Markdown 可以下载。

以上标准已按 Task 16 完成自动化与真实页面验收；调用外部模型的手动复验需要使用者提供自己的 OpenAI 兼容接口配置。

## 8. 下一阶段目标：稳定日常使用

下一阶段不增加新的阅读场景，只加固已有主流程，并保持各模块可独立测试和替换。

### 8.1 长文章可靠性

- 翻译前显示 Unicode 字符数和 Markdown 块数；当前以 30,000 字符为安全阈值，对更长内容给出模型上下文风险提示。
- 普通文章保持单次请求；长文章按 Markdown 块顺序串行翻译，标题、段落、列表、表格和代码围栏不跨请求拆开。
- 显示真实段落进度；失败后只重试未完成段，取消后保留已完成段。

### 8.2 Markdown 完整性

- 在请求前保护代码和链接目标，请求后恢复并校验。
- 发现结构缺失时不保存为完成结果，而是指出具体失败段并允许重试。

### 8.3 隐私与最小权限

- 正式端点只允许 HTTPS，本机调试地址可例外使用 HTTP。
- 请求前让用户看见内容将发送到哪个服务端点，并可清除已保存的 API Key。
- 正文只在用户操作后提取，站点与模型端点权限按需申请，不再长期申请所有网站权限。

### 8.4 数据耐久性与验证

- 最近结果与历史正文只保存一份，旧数据可平滑迁移；存储不足时给出可执行提示。
- 使用无真实密钥的 Chrome E2E 覆盖主流程；该自动化基线已完成，最终再用个人模型配置完成人工验收。

## 9. 下一阶段验收标准

1. 普通文章保持现有体验，长文章可分段完成且顺序正确。
2. 取消或单段失败不会丢失已完成译文，重试不重复请求成功段。
3. 代码、图片地址和普通链接地址在翻译前后保持一致。
4. Manifest 不再静态申请 `<all_urls>`，缺少权限时有明确恢复入口。
5. 旧历史可继续打开，本地容量不足不会悄悄丢失结果。
6. 自动化 Chrome 流程不依赖真实 API Key；真实模型复验步骤和结果有记录。

Task 24 已完成第 6 项的无密钥自动化部分。Task 25 已在五个真实站点完成生产扩展提取，并验证本机 OpenAI 兼容端点；当前本地 0.5B～7B 模型仍会改写部分 Markdown 保护标记，因此五站真实模型清单尚未通过，任务保持未完成。详见 [acceptance.md](./acceptance.md)。

## 10. 下一阶段仍不做

- 不做逐段对照编辑、术语表和翻译风格系统。
- 不做搜索、收藏、账号、云同步和跨设备恢复。
- 不做并发翻译、通用任务调度器或多服务商管理后台。
- 不处理 PDF、登录墙、跨域 iframe 和 Shadow DOM 正文。
