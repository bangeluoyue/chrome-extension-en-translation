# 任务拆分（Task Breakdown）

> 依据文档：
> - 需求：[proposal.md](../proposal.md)
> - 技术架构：[design.md](../design.md)
> - 页面布局：[01-弹窗页面.md](./layouts/01-弹窗页面.md)、[02-翻译结果页.md](./layouts/02-翻译结果页.md)、[03-设置页面.md](./layouts/03-设置页面.md)

本文档将实现工作拆分为若干**独立可完成、尽量低耦合**的任务模块，供 AI 分步骤实现。每个任务完成时都应能看到可感知的效果（可运行、可点击、可验证）。

## 1. 拆分原则

1. **按优先级分层**：P0（先跑起来）→ P1（核心链路）→ P2（页面功能）→ P3（收尾验收）。
2. **低依赖**：每个任务尽量减少前置依赖，可单独开发、单独验证。
3. **可见效果**：每个任务定义明确的"完成即能看到"的验收标准。
4. **任务可独立验收**：任务之间通过统一的类型与接口契约衔接，避免互相阻塞。

## 2. 任务总览

| 编号 | 优先级 | 任务 | 关联页面/模块 | 可见效果 |
|------|--------|------|---------------|----------|
| T1 | P0 | 工程初始化 | 全部页面（骨架） | 插件可加载，弹出空 Popup |
| T2 | P0 | 三页静态骨架与导航 | 01/02/03 全页 | 三页可切换，布局落地 |
| T3 | P1 | 正文内容提取 | 01「当前页面信息」 | 弹窗展示文章标题与原文 Markdown |
| T4 | P1 | 本地存储服务 | 03「保存」、结果持久化 | 数据可存可取、重启可恢复 |
| T5 | P1 | AI 流式翻译 | 02「正文渲染区」 | 能流式获取翻译文本 |
| T6 | P2 | 结果页打字机 + md-wx | 02 全页 | 翻译逐字显示并渲染 |
| T7 | P2 | 设置页配置功能 | 03 全页 | API Key/模型保存并生效 |
| T8 | P2 | 下载 Markdown | 01/02「下载」 | 下载 `.md` 文件，格式正确 |
| T9 | P3 | 端到端联调与验收 | 全部页面 | 需求验收标准全部通过 |

## 3. 依赖关系

```
T1 ──► T2 ──► T3 ──┐
            │       │
            │       ▼
            │      T4 ──► T5 ──► T6 ──► T8
            │                 │
            │                 ▼
            └────────────► T7 ──────────► T9
```

- **T1 → T2**：先有工程，再有页面骨架。
- **T2 → T3**：提取结果需展示在弹窗的「当前页面信息」区域。
- **T3 → T4**：提取结果需通过存储服务持久化。
- **T4 → T5**：翻译服务需读取存储中的 API Key 配置。
- **T5 → T6**：结果页将流式翻译文本逐字渲染。
- **T6 → T8**：下载需拿到完整翻译结果。
- **T7 → T5/T9**：设置页提供配置，供翻译与最终联调使用。
- 所有链路汇聚到 **T9** 做端到端验收。

> 说明：T7（设置页）与 T3/T4/T5 逻辑上相对独立，可在 T4 之后并行推进；图中为便于理解按串行绘制。

## 4. 任务详细说明

### T1 工程初始化（P0）

- **目标**：搭建可运行的 Chrome 扩展骨架工程。
- **关联页面/模块**：全部页面（仅入口骨架，无具体 UI）。
- **任务内容**：
  1. 初始化 Vite + React + TypeScript 工程。
  2. 安装依赖：`@mozilla/readability`、`turndown`、`turndown-plugin-gfm`、`openai`、`md-wx` 等。
  3. 配置 Manifest V3 与多入口构建（background / content / popup / 结果页 / 设置页）。
  4. 按 design.md 目录结构规范建立目录骨架。
- **验收标准**：插件能成功加载到 Chrome，点击图标弹出空 Popup。
- **依赖**：无。

### T2 三页静态骨架与导航（P0）

- **目标**：将布局文档中的三页以静态 UI 落地，并打通页面跳转。
- **关联页面/模块**：
  - 弹窗页：[01-弹窗页面.md](./layouts/01-弹窗页面.md)（顶栏、当前页面信息、一键翻译、下载、状态提示）
  - 结果页：[02-翻译结果页.md](./layouts/02-翻译结果页.md)（顶栏、元信息、正文区）
  - 设置页：[03-设置页面.md](./layouts/03-设置页面.md)（顶栏、表单区、保存）
- **任务内容**：
  1. 按 ASCII 布局实现三页静态结构（按钮、输入框、占位文本）。
  2. 实现页面间跳转：弹窗 ↔ 结果页、弹窗 ↔ 设置页。
- **验收标准**：三页可正常切换，各模块布局与示意图一致。
- **依赖**：T1。

### T3 正文内容提取（P1）

- **目标**：在 Content Script 中用 Readability + Turndown 提取正文并转为 Markdown。
- **关联页面/模块**：[01-弹窗页面.md](./layouts/01-弹窗页面.md)「当前页面信息」「一键翻译」。
- **任务内容**：
  1. 实现 Content Script：Readability 抽取正文 → Turndown 转 Markdown。
  2. 提取元信息：标题、作者、原文链接，图片转换为 `![alt](src)`。
  3. 通过消息机制将结果返回给 Popup。
  4. 在弹窗「当前页面信息」区域展示文章标题与提取状态。
- **验收标准**：在任意英文文章页点击后，弹窗能看到文章标题与提取出的 Markdown 原文。
- **依赖**：T2。

### T4 本地存储服务（P1）

- **目标**：实现 `chrome.storage.local` 读写能力。
- **关联页面/模块**：[03-设置页面.md](./layouts/03-设置页面.md)「保存」、最近一次结果持久化。
- **任务内容**：
  1. 定义存储结构（最近一次翻译结果、用户配置）。
  2. 实现存储服务的读写接口（保存/读取/覆盖）。
  3. 与消息机制对接，供其他模块调用。
- **验收标准**：能写入并读取数据，重启插件后数据仍可恢复。
- **依赖**：T1（可提前并行）。

### T5 AI 流式翻译（P1）

- **目标**：用 OpenAI SDK 兼容方式调用 Qwen，实现流式翻译。
- **关联页面/模块**：[02-翻译结果页.md](./layouts/02-翻译结果页.md)「正文渲染区」。
- **任务内容**：
  1. 封装 OpenAI SDK 客户端（可配置 `baseURL` / `model` / `apiKey`）。
  2. 设计翻译提示词（英译中、保留 Markdown 与图片格式）。
  3. 实现流式调用，逐块返回翻译增量。
- **验收标准**：配置 API Key 后，能流式获取到翻译文本片段。
- **依赖**：T4（读取配置）。

### T6 结果页打字机 + md-wx 渲染（P2）

- **目标**：结果页将流式翻译逐字展示，并用 md-wx 渲染 Markdown。
- **关联页面/模块**：[02-翻译结果页.md](./layouts/02-翻译结果页.md) 全页。
- **任务内容**：
  1. 接入 `md-wx` 组件，渲染 Markdown。
  2. 将流式增量累积并更新 `markdown`，实现打字机效果。
  3. 拼接固定输出格式（标题/作者/原文链接 + 正文）。
  4. 实现复制按钮。
- **验收标准**：翻译结果逐字显示，Markdown 正确渲染，可复制完整结果。
- **依赖**：T5。

### T7 设置页配置功能（P2）

- **目标**：设置页可保存 API Key、模型、Base URL 配置。
- **关联页面/模块**：[03-设置页面.md](./layouts/03-设置页面.md) 全页。
- **任务内容**：
  1. 实现表单输入与下拉选择（API Key / 模型 / Base URL）。
  2. 保存配置到存储服务。
  3. 读取并回填已有配置。
- **验收标准**：配置保存成功，重新打开设置页能回显，翻译服务能使用该配置。
- **依赖**：T4。

### T8 下载 Markdown（P2）

- **目标**：将翻译结果按固定格式下载为 `.md` 文件。
- **关联页面/模块**：
  - [01-弹窗页面.md](./layouts/01-弹窗页面.md)「下载 Markdown」
  - [02-翻译结果页.md](./layouts/02-翻译结果页.md)「下载」
- **任务内容**：
  1. 拼接 proposal 3.6 固定输出格式。
  2. 触发浏览器下载，生成 `.md` 文件。
  3. 无结果时禁用下载按钮。
- **验收标准**：下载的文件内容格式严格符合需求 3.6 规定。
- **依赖**：T6。

### T9 端到端联调与验收（P3）

- **目标**：打通完整链路并完善错误处理。
- **关联页面/模块**：全部页面。
- **任务内容**：
  1. 端到端联调：提取 → 翻译 → 展示 → 下载。
  2. 完善错误处理：提取失败、翻译失败、API Key 缺失、网络异常等。
  3. 逐项核对 proposal.md 第 6 节验收标准。
- **验收标准**：proposal.md 第 6 节全部验收标准通过。
- **依赖**：T3、T6、T7、T8。

## 5. 执行顺序建议

按依赖关系顺序执行：**T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8 → T9**。

- T4、T7（存储与设置）可在 T3 之后与 T5/T6 并行推进，以降低阻塞。
- 每个任务完成后单独验证其"可见效果"，再进入下一任务。
