# AI 双语文章阅读助手 — 迭代实施清单

## 1. 使用方式

这份清单用于让 AI 按顺序推进 Demo 和后续稳定性迭代。每次只执行一个编号任务，完成并验证后再进入下一项。

可以直接对 AI 说：

> 继续实现 task.md 中第一个未完成任务，只做该任务范围，完成后验证并更新状态。

## 2. AI 执行规则

1. 开始前将当前任务标记为 `[~] 进行中`。
2. 先检查现有实现，优先复用，不重复创建相同组件或工具函数。
3. 只实现当前任务，不顺带开发后续任务。
4. 被新实现替代的旧代码、无效配置和未使用依赖在当前任务中删除。
5. 每个任务都要产生可直接看到或操作的效果。
6. 完成后至少执行类型检查、相关测试和生产构建。
7. 验收通过后标记为 `[x] 已完成`，并同步受影响的设计或布局文档。
8. 若必须由用户在 Chrome 中确认，AI 应列出最短验证步骤，但不得提前实现下一任务。
9. 新增能力按“纯逻辑、流程接入、界面反馈、验收”拆分；不同模块不得共享可变运行状态。
10. 后续任务只能依赖清单中明确标出的前置任务，不为尚未开始的任务预埋抽象层。

任务 00 和 01 是已完成的项目基础；“每项都有可见效果”的要求从功能任务 02 开始执行。任务 17～24 已完成，任务 25 仍按清单顺序推进。

## 3. 优先级说明

- **P0 · 核心阅读**：决定这个工具能否每天使用，优先完成。
- **P1 · 阅读效率**：减少查词、找回结果和整理内容的操作成本。
- **P2 · Demo 完成度**：统一界面、清理冗余并完成真实场景验收。

第二阶段沿用 P0～P2，但含义调整为：P0 解决翻译可靠性，P1 收紧安全与数据边界，P2 建立发布前验证信心。

## 5. 模块实施卡

### M1 · 阅读工作区（P0）

完成后可见效果：用户能在原网页旁阅读原文、译文或完整双语内容，重新打开后保持上次模式。

#### 03 · 三种阅读模式

- 在共享阅读界面加入“仅译文 / 双语 / 仅原文”切换。
- 仅译文展示当前译文；仅原文展示提取出的 Markdown；双语按原文在上、译文在下展示。
- Side Panel 与 Result 复用同一模式组件。
- 本任务不保存阅读模式，不做逐段对齐。
- 验收：三个按钮即时切换内容，翻译中也能查看已经提取的原文。

#### 04 · 模式记忆与窄宽适配

- 将阅读模式保存到现有用户配置或独立轻量存储键。
- 重新打开 Side Panel 和 Result 时恢复上次模式。
- 表格和代码块在窄侧边栏中横向滚动，操作栏不遮挡正文。
- 验收：切换模式后重新打开仍保持；常见窄宽下没有关键内容溢出。

### M2 · 翻译控制（P0）

完成后可见效果：长文章翻译不再只能等待，用户可以停止、重试，并清楚知道当前发生了什么。

#### 05 · 取消与重新翻译

- 将同一个 `AbortSignal` 传入打字机消费和真实模型请求。
- 翻译中显示“取消”；取消后停止接收内容并保留当前临时译文。
- 取消、失败或完成后可以“重新翻译”，重新开始时清空旧临时译文。
- 本任务不做分段重试和断点续传。
- 验收：点击取消后请求终止；点击重新翻译只产生一个新请求。

#### 06 · 完整状态反馈

- 统一 `loading / streaming / complete / cancelled / error / empty` 状态和文案。
- 区分配置缺失、网络、认证、模型和正文提取错误。
- 每种异常都给出下一步操作，并防止重复提交。
- 验收：通过 Mock 或手动方式看到主要状态，按钮可用性与状态一致。

### M3 · 模型设置（P0）

完成后可见效果：用户可以配置任意 OpenAI 兼容模型，并在翻译文章前确认配置有效。

#### 07 · 自由输入模型名称

- 将固定模型下拉框改为可输入字段，并用建议列表保留常用模型。
- API Key 输入默认隐藏具体字符。
- 保持旧配置可正常回填和保存。
- 不引入多服务商、多套配置和高级参数。
- 验收：可输入列表外模型名，保存后重新打开仍能正确显示。

#### 08 · 测试连接

- 使用当前表单中的 API Key、模型和 Base URL 发起最小测试请求，无需先保存。
- 显示测试中、成功和分类失败状态，测试期间禁止重复点击。
- 测试不得创建文章结果或历史记录。
- 验收：正确配置能看到成功反馈；错误 Key 或模型名能看到明确原因。

### M4 · 划词翻译（P1）

完成后可见效果：网页中遇到不理解的句子时，可右键在侧边栏直接查看译文，不打断整篇阅读。

#### 09 · 右键入口与原文卡片

- 添加仅在选中文字时出现的右键菜单。
- Background 将选中文字、页面标题和 URL 交给 Side Panel。
- Side Panel 顶部显示可关闭的划词原文卡片。
- 本任务不调用模型，先确认入口和数据传递可见。
- 验收：在普通网页选中文字并点击菜单，侧边栏显示完全一致的原文。

#### 10 · 划词译文与复制

- 复用现有模型配置和翻译服务生成简短译文。
- 卡片显示翻译中、成功和失败状态，并支持复制译文。
- 新划词替换上一条临时结果，不覆盖整篇文章，不写入历史。
- 验收：连续翻译两段选中文字时，文章阅读结果保持不变。

### M5 · 最近历史（P1）

完成后可见效果：最近翻译过的文章可以直接找回，不需要再次调用模型。

#### 11 · 保存与历史列表

- 翻译成功后写入 `translationHistory`，最新记录排在最前面。
- 相同结果避免重复插入，最多保留 20 篇。
- 在 Side Panel 中增加历史视图，显示标题、站点和时间。
- 继续使用 `chrome.storage.local`，不引入 IndexedDB。
- 验收：连续完成两篇翻译后，历史视图按时间显示两条记录。

#### 12 · 打开与删除

- 点击历史记录回到阅读视图并展示保存结果，不重新请求模型。
- 支持删除单条记录，并避免删除后仍显示旧内容。
- 不做搜索、收藏、分页和批量管理。
- 验收：打开历史时没有模型请求；删除后列表和最近结果状态一致。

### M6 · 内容输出（P1）

完成后可见效果：用户可以把译文或双语内容直接保存到笔记工具中。

#### 13 · 两种复制模式

- 提供“仅译文 Markdown”和“双语 Markdown”两个复制选项。
- 抽取一个共享格式化函数供 Side Panel 与 Result 使用。
- 输出包含标题、作者和原文链接，复制结果与当前阅读模式无关。
- 验收：两种复制结果结构正确，界面给出成功或失败反馈。

#### 14 · 双语 Markdown 下载

- 下载内容包含元信息、完整原文和完整译文。
- 复用任务 13 的格式化逻辑，不再保留功能重复的旧格式化代码。
- 文件名来自文章标题并清理非法字符。
- 验收：下载文件可正常打开，正文与复制的双语结构一致。

### M7 · Demo 完成度（P2）

完成后可见效果：入口更简洁，常见文章站点可以稳定使用，代码和文档与实际功能一致。

#### 15 · 界面收口与冗余清理

- Popup 只保留当前网页、主按钮、最近一篇和设置入口。
- 移除 Popup 中完整 Markdown 预览与重复下载入口。
- Side Panel 与 Result 复用阅读、状态和输出组件，只保留各自必要导航。
- 删除未使用的组件、类型、工具函数、配置和依赖。
- 验收：四个界面职责与 layouts 文档一致，构建无未使用代码错误。

#### 16 · 真实场景验收

- 至少试用 5 篇来自不同网站的英文技术文章或博客。
- 修复阻断主流程的问题和明显布局缺陷，不在本任务新增功能。
- 检查空内容、长标题、代码块、表格、图片和超长文章。
- 执行完整检查并同步 README、proposal、design、layouts 和本清单状态。
- 验收：从配置到提取、翻译、阅读、划词、历史和输出的主流程可完整演示。

### M8 · 长文章可靠性（第二阶段 P0）

完成后可见效果：普通文章保持当前速度，长文章能看到规模与真实进度；单段失败或取消不会丢失已完成译文。

#### 17 · 文章规模预检

- 增加独立的纯函数计算字符数和 Markdown 块数，不调用模型、不读写存储。
- 在共享阅读界面请求前显示文章规模；超过安全阈值时提示可能受到模型上下文限制。
- 本任务不拆分请求、不修改翻译结果结构。
- 验收：普通文章和长文章显示不同但准确的预检反馈，现有单次翻译行为不变。

#### 18 · 顺序分段翻译

- 复用任务 17 的 Markdown 块信息，按标题、段落、列表、表格和代码围栏生成安全分段。
- 翻译服务按顺序请求各段并持续合并输出；同一时间只允许一个模型请求。
- 分段器保持为无 Chrome、React 和存储依赖的纯模块。
- 本任务不做失败段重试和断点持久化。
- 验收：超过单次安全阈值的文章产生多个请求，合并后的块顺序与原文一致；普通文章仍只请求一次。

#### 19 · 分段进度与恢复

- 阅读界面显示“正在翻译第 N/M 段”，不使用虚假百分比。
- 取消或失败时保留已完成段；重试只从第一个未完成段继续。
- 临时进度使用独立存储键，与完成结果和历史记录分开；完成、换文章或明确重译后清理。
- 本任务不增加并发、跨设备恢复或后台常驻任务。
- 验收：中间段失败后已完成段不重复请求；关闭再打开侧边栏可恢复同一篇文章的本地进度。

### M9 · Markdown 完整性（第二阶段 P0）

完成后可见效果：模型不能静默改写代码和资源地址，结构异常会明确落到对应段，而不是保存损坏结果。

#### 20 · 结构保护与校验

- 请求前用独立纯函数保护围栏代码、行内代码、图片 URL 和普通链接目标，请求后恢复原值。
- 校验保护标记数量、顺序与 Markdown 围栏是否完整；校验异常视为当前段失败。
- 结构保护只包装翻译服务，不依赖分段调度实现；划词翻译不接入该流程。
- 本任务不做术语表或全文语义质量评分。
- 验收：代码与 URL 按字节保持一致；模拟模型删除标记时不会保存完成结果，并可复用任务 19 的段重试。

### M10 · 端点与权限安全（第二阶段 P1）

完成后可见效果：用户能明确知道正文发往哪里，普通浏览时扩展不再长期拥有读取所有网站的权限。

#### 21 · 端点安全与数据去向

- 正式模型端点仅允许 HTTPS；只对 localhost 和 127.0.0.1 允许 HTTP 调试。
- Settings 明确显示文章与划词内容将发送到的主机，并提供清除已保存 API Key 的操作。
- 端点校验封装为共享纯函数，保存、测试连接和翻译使用同一规则。
- 本任务不调整 Manifest 权限、不增加代理服务或密钥加密口令。
- 验收：普通 HTTP 端点无法保存或测试，本机 HTTP 可用；清除后存储与表单都不再包含 Key。

#### 22 · 按需权限

- 移除静态 `<all_urls>` Content Script 和长期站点权限，点击翻译时通过 `activeTab` 与 `scripting` 注入提取逻辑。
- 模型端点使用可选 Host Permission，在用户保存或测试配置的操作中按需申请。
- 将权限申请封装在浏览器适配层，正文提取和翻译服务不直接调用 `chrome.permissions`。
- 本任务不改变正文算法、翻译提示词或阅读界面功能。
- 验收：Manifest 不再声明静态 `<all_urls>`；允许权限后提取、划词和模型请求仍可用，拒绝时给出明确下一步。

### M11 · 本地存储耐久性（第二阶段 P1）

完成后可见效果：长文章不会因为最近结果与历史重复保存而浪费空间，旧版本数据仍可打开。

#### 23 · 去重、迁移与容量错误

- 完整文章结果按 ID 只存一份，最近结果与历史列表只保存引用和轻量元信息。
- 增加单向、幂等的存储版本迁移；读取旧结构时自动迁移，不要求用户清空数据。
- 写入前后检查容量，超限时优先清理最旧历史，并在仍失败时展示可操作提示。
- 本任务不引入 IndexedDB、搜索、收藏、云同步或翻译缓存。
- 验收：旧数据迁移后内容不丢失；同一结果不重复保存正文；容量错误不会覆盖现有最近结果。

### M12 · Chrome 真实流程验证（第二阶段 P2）

完成后可见效果：核心闭环可以在真实 Chromium 扩展环境中重复验证，不再只依赖 jsdom 和人工点击。

#### 24 · 无密钥 Chrome E2E

- 建立独立 E2E 目录和命令，加载生产构建的 MV3 扩展并连接本地假 OpenAI 兼容服务。
- 覆盖设置、权限申请、网页提取、分段翻译、阅读、划词、历史、复制和下载主路径。
- E2E 夹具与 Vitest 单元测试分开，不让产品模块依赖测试服务器。
- 本任务不访问公网、不使用真实 API Key、不做跨浏览器矩阵。
- 验收：全新浏览器配置可一条命令跑通核心闭环，CI 失败时保留截图或追踪文件。

#### 25 · 稳定性验收与文档收口

- 在真实 Chrome 中使用个人模型配置复验至少 5 个不同站点，包含普通文章和超长文章。
- 验证 HTTPS/本机端点、允许/拒绝权限、取消恢复、结构校验、存储迁移和输出文件。
- 只修复阻断上述流程的问题，不在验收任务新增功能。
