# 05 · 稳定性与隐私交互

> 状态：长文章可靠性、Markdown 结构保护、端点最小权限与存储耐久性（任务 17～23）已实现。任务 25 的真实模型复验仍未通过，现有页面布局仍以 01～04 为准。

下一阶段不增加新页面，只给 Reader 和 Settings 补充对用户决策有用的信息。普通短文章保持当前简洁界面。

## 1. 长文章状态

任务 17 显示文章规模，任务 18 接入顺序分段请求，任务 19 加入真实进度和本地恢复。

```text
┌────────────────────────────────────┐
│  Long Technical Article            │
│  38,000 字符 · 长文章 · 112 个块     │
│  文章较长，将按 Markdown 结构分段。   │
│                                    │
│  ● 正在翻译第 3/8 段         [取消]  │
│  已完成段会保存到本地，可继续翻译。    │
└────────────────────────────────────┘
```

- 任务 17 按 Unicode 字符计算长度，并显示 Markdown 块数；30,000 字符及以下标记为“普通文章”，更长内容标记为“长文章”。
- 普通文章只显示一行简洁规模并保持单次请求；长文章额外提示将按 Markdown 结构顺序分段。
- 分段器以 30,000 字符为片段上限，按原文顺序打包完整块；列表、表格和代码围栏不会在内部切开，单个超限原子块仍保持完整。
- 块数是原文结构规模，不是翻译请求段数；多段文章另显示真实的“第 N/M 段”，不计算虚假百分比。
- 每个完整段结束后保存独立检查点；取消、失败或关闭侧边栏不会丢失这些段，继续时从首个未完成段恢复。
- 新文章、完成结果和明确重新翻译会清除检查点。

## 2. Markdown 结构校验失败

```text
┌────────────────────────────────────┐
│  第 3/8 段翻译失败，已完成 2/8 段。  │
│  Markdown 结构校验失败：标记数量不一致 │
│              [继续翻译] [重新翻译]  │
└────────────────────────────────────┘
```

- 围栏代码、行内代码、图片 URL 和普通链接目标在模型请求前替换为有序标记，响应时按字节恢复。
- 标记数量或顺序变化、标记残缺、代码围栏不完整都视为当前段失败；失败段不写入检查点或完成结果。
- “继续翻译”复用任务 19 的检查点并重试当前段。划词翻译不接入 Markdown 结构保护。
- 真实模型复验中，标记被删除、重复或改写时状态区按上述方式失败，复制与下载保持禁用；不得因个别重试偶发成功而隐藏模型兼容性问题。

## 3. 数据去向与端点安全

Settings 在 Base URL 下方展示规范化后的目标主机，并将清除 Key 与保存配置分开。

```text
Base URL  [https://api.example.com/v1      ]
文章正文和划词内容将发送到 api.example.com
模型端点权限：已允许

[清除 API Key]       [测试连接] [保存]
```

- HTTP 非本机地址在字段旁直接报错，不能保存或测试；localhost 与 127.0.0.1 调试明确标记为“不安全的本机 HTTP 调试连接”。
- 数据发送主机来自与翻译服务相同的纯端点校验器，不根据未校验字符串拼接展示。
- 清除 API Key 需要一次确认，但不删除模型、Base URL、历史和文章结果。
- 保存或测试连接时只申请当前模型主机权限；拒绝后不保存或发起测试，并提示再次点击操作后在浏览器提示中允许。
- 普通浏览不再静态注入正文脚本；只有点击 Popup 主操作后才通过当前标签页临时权限注入。
- 旧配置缺少模型主机权限时，整篇与划词翻译不会发出请求，并引导用户回 Settings 授权。

## 4. 存储容量反馈

- 自动清理最旧历史时使用一次轻量提示，不打断当前阅读。
- 清理后仍无法保存时显示“译文已生成但未保存”，并保留复制与下载操作。
- Popup 保存待翻译文章失败时提示先删除较早历史或清理扩展本地数据，不打开空的阅读工作区。
- 容量失败不会替换之前的最近结果；当前内存中的完成译文仍可立即复制或下载。
- 不展示技术性的字节数、存储键或迁移版本。

## 5. 交互边界

- Side Panel 与 Result 复用同一长文状态，不维护两套进度文案。
- 权限状态与申请只属于 Settings；Popup 只负责用户触发的当前标签页注入，Reader 在缺少模型权限时提供设置入口。
- 分段、结构保护、权限和存储错误分别映射到既有状态区，不新增全局通知系统。
